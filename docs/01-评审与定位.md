# 评审与定位：文献证据工作台

> **v0.2 修订（2026-11-11）** — 约束变更：① 只做 Web 版；② 主仓 MIT 开源；③ 面向全领域、按图表占比最高准备；④ 优先复用开源组件。
>
> 因此本文两处结论作废：
> - 「主体形态 = 独立桌面软件」→ 改为**自部署 Web 应用**，见 [03-架构与路线](03-架构与路线.md)；
> - 「不要自建任何轮子」的取舍不变，但「从零实现解析」的假设作废，复用策略见 [02-开源复用与许可证](02-开源复用与许可证.md)。
>
> **不变**：功能判定（1/2/3 商品化、4/6 是空白）、该砍清单、引用校验是护城河、图表要重定义为「图证据库 + 引用建议 + 曲线数字化」。

> 定位：**不是"AI 读文献工具"，是"文献证据中间层"**。
> 把文献里的可引用证据（段落 / 表 / 图 / 曲线 / 数据点）变成结构化、可检索、可溯源、能直接进写作流程的资产。

## 0. 结论先行

| 问题 | 结论 |
| --- | --- |
| 值不值得做 | 值得，但价值不在"读"，在"写"和"图" |
| 六个功能里哪些是壁垒 | 只有 4（起草+引注）和 6（图表）是，1/2/3/5 是采购与封装 |
| 最终形态 | 本地优先的桌面应用为主体；Zotero 是上游；MCP 是下游出口；LaTeX/Overleaf 是终点 |
| MCP 是不是产品 | 不是。它是 agent 的接口，不是人的界面 |
| 最大的技术风险 | 图-caption 绑定准确率（决定 F6 是否成立） |
| 最大的工程风险 | 范围爆炸（6 功能 × 深度 ≈ 18 个月） |

## 1. 与现有工具的能力对照

| 能力 | 现有工具状态 | 你的空间 |
| --- | --- | --- |
| 扫描件 OCR | Docling(MIT) / MinerU(AGPL) / Marker(GPL+权重条款) / PaddleOCR-VL 均成熟 | 无。只做路由、降级、缓存 |
| 单篇结构化总结 | MIT 许可的 Zotero 插件已实现中文结构化摘要（含 limitations / 证据质量 / 复现性） | 小。做成卡片的视图即可 |
| 多文档问答 | 同上，带 `[文献2·D2-P14]` 式证据编号 | 小。别当卖点 |
| 引用条目复制 | Zotero 原生（CSL 全样式） | 无 |
| **图表级证据抽取与复用** | **基本空白** | **大** |
| **跨文献对比矩阵** | 空白（Elicit 类只给文字回答，不给可编辑表） | **大** |
| **骨架 + 证据挂载 + 引用校验** | 空白 | **大** |
| **曲线数字化重绘** | WebPlotDigitizer 手工，无工作流整合 | **大** |
| 中文学位论文模板 | 国外工具不做 | 中 |

结论：1~3 已被商品化，验证了需求，也说明它们不是壁垒。差异化必须在 4/6。

## 2. 能力边界（做什么 / 不做什么）

**做**
- PDF → block 级真值（页码 + bbox + 类型 + 阅读顺序）
- 固定 schema 的论文卡片 + 论断级 claim 库
- 图/表证据库（绑定 caption、可检索、带许可提示）
- 跨文献对比矩阵 → 导出 LaTeX 表
- 反向大纲 + 证据缺口检测
- LaTeX 骨架 + `\cite{}` 占位 + 引用一致性校验
- 曲线数字化 → 重绘
- 导出：BibTeX / LaTeX / Overleaf(Git)

**不做**
- 自建 PDF 阅读器 / 文献管理器（寄生 Zotero）
- 通用"和文献对话"、自由文本"一键总结"（已商品化）
- 全自动写论文正文（学术风险 + 用户不信任）
- LLM 自由打主题标签（不可复现）
- 知识图谱可视化大屏
- 自研 OCR 模型
- 移动端 / 实时协作（首版）

## 3. 数据模型（SQLite 草案）

设计原则：**任何 AI 产出都必须可回溯到 block**。这不是提示词里的君子协定，是数据库约束。

```sql
-- 文献
paper(id PK, doi, title, year, venue, authors_json,
      zotero_key, pdf_sha256, status)          -- status: new|parsed|carded|drafted

-- 解析产物：唯一真值
block(id PK, paper_id, page INT, bbox_json, type TEXT,
      -- text|title|section|table|figure|caption|formula|ref|header|footer
      text TEXT, order_idx INT, parent_id, engine TEXT, conf REAL)

figure(id PK, paper_id, block_id, page, bbox_json,
       image_path, caption, label, subfig_json,
       license_hint)                            -- reuse|permission|redraw

tab(id PK, paper_id, block_id, page, html, cells_json, caption)

-- 结构化卡片（LLM 抽取）
card(id PK, paper_id, schema_ver, fields_json,
     model, prompt_hash, created_at)
card_field(card_id, key, value, evidence_block_ids JSON, conf REAL)

-- 论断级证据（写作时的检索单位）
claim(id PK, paper_id, text, polarity,
      conditions_json,                          -- {样品, 温度区间, 假设, 边界}
      evidence_block_ids JSON)

-- 主题（受控词表，不是 LLM 自由标签）
topic(id PK, name, parent_id)
paper_topic(paper_id, topic_id, source TEXT, conf)

-- 写作侧
project(id PK, title, template_id, venue)
outline_node(id PK, project_id, parent_id, title, order_idx, claim_ids JSON)
draft(id PK, project_id, latex, updated_at)
cite_anchor(id PK, draft_id, sentence_hash, paper_id,
            block_ids JSON, verdict)            -- ok|weak|unsupported

-- 工程
job(id PK, kind, paper_id, status, progress,
    error, attempts, started_at, finished_at)
```

关键不变量：
- `card_field.evidence_block_ids`、`claim.evidence_block_ids`、`cite_anchor.block_ids` 非空才允许落库；
- 页面高亮只依赖 `block.bbox`，不做二次 OCR 对齐。

## 4. 解析管线

```
导入 → 去重(sha256) → 元数据(Zotero/DOI) → 逐页判断有文字层
   ├─ 有 → 轻量解析(pymupdf / Docling)
   └─ 无 → OCR(Docling+OCR | MinerU | PaddleOCR-VL)
→ block 归一化（统一 bbox 坐标系、阅读顺序、类型）
→ 图/表/Caption 绑定
→ 卡片抽取（结构化输出，失败重试/降级）
→ 入索引（BM25 + 向量 + metadata）
```

三个必须有的工程件：
1. **路由**：不要对全部 PDF 跑 OCR，成本差 10 倍以上。
2. **降级**：解析失败时渲染页面 → VLM 直读，并把失败块标 `conf=0`，绝不静默丢字。
3. **缓存**：按 `pdf_sha256 + engine_version + prompt_hash` 缓存，换模型可重跑、不重复花钱。

选型（许可证优先）：
- Docling：MIT，结构化 doc model，表格强 → 基线
- MinerU：AGPL-3.0，学术 PDF 最强（公式/双栏/图表 caption）→ 增强档；闭源分发需评估
- Marker：代码 GPL-3.0，权重有商业收入门槛条款 → 谨慎
- PaddleOCR-VL / olmOCR → 纯 OCR 备选

## 5. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 + React | 体积小，能托管 sidecar 进程 |
| PDF 渲染 | PDF.js | 能用 bbox 画高亮，跨平台 |
| 后端 | Python FastAPI（sidecar） | 解析/OCR/ML 生态全在 Python |
| 存储 | SQLite + 本地文件目录 | 单机零运维；团队版换 Postgres + 对象存储 |
| 向量 | sqlite-vec 或 LanceDB | 不引入独立服务 |
| 队列 | SQLite job 表 + worker 进程 | 先简单；团队版 Redis + RQ |
| LLM | OpenAI 兼容抽象 | 云 / 本地 vLLM / Ollama 随便换 |
| 引用 | citeproc-js + CSL + BibTeX | 不自己实现样式 |
| 模板 | 独立 Git 仓库，变量映射 | 可社区贡献，避免维护 100 个学位模板 |

Zotero 集成注意：Zotero 运行时 `zotero.sqlite` 被锁，**不要直接读库**；用 Zotero 7+ 的本地 HTTP API（`http://localhost:23119/api/`），失败再回退到只读快照。

## 6. MCP 工具面（下游出口，5 个）

原则：**工具少而粗，返回 ID 而不是长文本**，让 agent 自己做决策；MCP 只读，写操作走 UI（防污染库）。

1. `library.search(query, filters)` → `[{paper_id,title,year,why}]`
2. `evidence.get(paper_id|claim_id)` → `[{block_id,page,bbox,text}]`
3. `figure.list(topic|paper_id)` → `[{figure_id,caption,license_hint}]`
4. `cite.resolve(claim_text, candidate_ids)` → `[{paper_id,block_ids,verdict}]`
5. `draft.outline(project_id)` → LaTeX 骨架

## 7. 评测集（决定项目是 demo 还是工程）

- **Gold set**：20 篇（含 5 篇扫描件），人工标注 100 个 block 边界、30 对图-caption、10 张表、50 条 claim。
- **指标**：block 边界 F1 / 图-caption 绑定准确率 / 表格单元格级还原率 / 公式 exact match / 卡片字段准确率（人工 1–5 分）/ 引用定位准确率（点击是否跳到正确句）。
- **纪律**：每次换解析引擎或抽取模型都重跑，防止"看起来更聪明了其实更差"。

## 8. 里程碑

| 阶段 | 周期 | 产出 | 验收 |
| --- | --- | --- | --- |
| P0 可行性验证 | 1 周 | 20 篇领域 PDF 跑 Docling/MinerU，人工标注 | 图-caption 绑定 ≥80%，表格可读率 ≥70% |
| P1 证据地基 | 4 周 | 导入 → 解析 → block 库 → PDF 高亮 → 单篇卡片 → BibTeX | 任意结论一次点击跳回原页原文 |
| P2 写作侧 | 4–6 周 | 对比矩阵、反向大纲、LaTeX 骨架 + 引用校验 | 10 篇 → 一份可编译综述骨架，引用全部可回查 |
| P3 图表与分发 | 4–6 周 | 图库、曲线数字化、模板库、Overleaf 同步、MCP、Docker | 一套模板出 PDF；3 人课题组共用 |

**P0 是 go/no-go 关口**：绑定率不到 80%，F6 不成立，差异化要重新设计。

## 9. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 范围爆炸 | 18 个月做不完 | 砍到 3 个功能先跑通闭环 |
| 图-caption 绑定上限 ~80% | F6 可信度 | 人工纠错 UI + 置信度标注 |
| 扫描中文老文献 | 老综述不可用 | 明确支持边界，标"低质量"而不是假装成功 |
| 版权 | 图复用/团队共享 | 三档许可提示 + 只做引用/重绘，不做图片搬运 |
| token 成本 | 100 篇 × 3 次抽取 ≈ 数百万 token | 分级抽取（摘要级/全文级）+ 本地小模型预处理 |
| 长任务稳定性 | 批处理中断 | 断点续跑 + 幂等 job |
| Zotero 耦合 | 大版本改 API | 走官方本地 API，不直接改库 |
