## 2. 链路是怎么跑的（不是脚本级，是产品链路）

```
POST /api/papers（5 份 PDF，流式 sha256）
        │
        ▼
job(backend=pdfium)  ← 默认档，秒级
        │
        ├─ 有文字层且判弱（缺锚定图号）→ 自动排 job(backend=docling)      → 书 01/02
        └─ 无文字层（text_layer=False）→ 自动排 job(backend=mineru, ocr) → 书 03/04/05
        ▼
persist（先删后插，按 cite_key 保留人工复核）
```

- API 与 worker 是两个进程，共用同一个 SQLite 库与 storage；worker 从 ASCII 目录联接
  `C:\litbench` 启动（Docling 的 C++ 解析层打不开中文路径，见 `docs/09` §11）。
- 本次是**全新库**：`scripts/seed_dev.py` 的 9 篇 arXiv + 5 本课本 = 14 篇。
- 时间：21:04 上传（job 表存 UTC，+8 换算），串行消费，5 本合计约 3 分 36 秒
  （不含第一次 pdfium 快跑）。

## 5. 《自动控制原理》`figures=0` 的结论：不是 bug，是探针取样点不对

之前 `docs/11` 的「书 03 前 2 页 figures=0」来自 **1–2 页的探针口径**，
而这两页恰好是章节开篇：

- 第 1 页：章标题 + 3 段引言 + 4.1 节开头，**全是正文与公式**（equation 块 6 个），没有图；
- 第 2 页：承接正文与公式（equation 块多个），也没有图；
- 整章 47 页里，有 11 页没有任何 image/chart 块，图从**第 3 页**开始出现
  （p3 起 2 张/页，p4–p13 约 4 张/页，p15 有 8 个图块——图 4.3.x 的多子图被拆开）。

所以「前 2 页 0 张图」是取样偏差；整章 104 张、其中 44 个不同图号。
**指标必须带页范围和样本量**（这条已写进 `docs/09` §12.4 的教训）。

## 6. 已知缺口（诚实写，别把数字当精度）

1. **书 01/02 的文字层是出版社 OCR 的产物，图号本身有错字。**
   典型：`图 162`（应为 `图 1-2`）、`图 10/0`（应为 `图 10-10`）、`图 4.e.1`（习题图）。
   这不是解析器新增的错——原文字层就长这样；要修得对这两本也走 OCR（或人工复核）。
   对应地，这两本 `label_norm` 里有 5 张图是 `fig:10` 这种退化号。
2. **MinerU flash 的图是「图块」粒度，一图多子图会拆成多行 figure。**
   所以 104 张图里只有 44 个不同图号；同号多行不是重复落库，是 (a)/(b)/(c) 子图各占一行。
   当前只把图号挂到与图注几何重合的那一行，其它子图行留空，等 review 通道/后续做子图归并。
3. **MinerU flash 的表格是 markdown 文本，不是结构化 HTML。**
   整章确实会出少量 `table` 块（书 03 有 4 个、书 05 有 2 个；`docs/11` 前 2 页口径下为 0），
   表题/表体也是嵌在 table 块里的子块，适配器已能取出表题与表体文本，但 `html` 仍为空。
   需要结构化表格时走 Docling（见 `docs/11` 选型）。
4. **图注覆盖率不是 100%。** 书 01 有图注 33/46、书 02 41/72；其余是 Docling 拆散的多面板图
   与没挂上图注的图块。按产品原则不调阈值硬凑，走 review + agent 纠错。
5. **没有做「图注内容正确率」的人工标注。** 本次只验证了「图号能检索到、框在图上、
   缩略图不是正文」。图注文本本身（尤其 OCR 书的）仍需抽样校对，这是下一步（`docs/10` 第 4 步）。
6. **Docling 在密排扫描页上仍会病态慢**（`docs/11`）：书 03/04 的 Docling OCR 跑不完，
   所以本次三本无文字层的书统一走 MinerU flash，没有做同书双后端对照。

## 8. 复现命令

```powershell
# 1) worker 必须从 ASCII 目录启动（Docling 限制）
$env:DATABASE_URL='sqlite+aiosqlite:///<repo>/.data/dev.db'
$env:STORAGE_DIR='C:\litbench\.data'
$env:PYTHONPATH='C:\litbench\server'
$env:HF_HOME='C:\litbench\.hf-cache'
$env:HF_ENDPOINT='https://hf-mirror.com'
$env:MINERU_HOME='C:\litbench\.data\mineru-home'
$env:MINERU_MODEL_SOURCE='modelscope'
Set-Location 'C:\litbench'
C:\litbench\.venv\Scripts\python.exe -m litbench.workers.run --poll 1

# 2) 另开：API
$env:STORAGE_DIR='<repo>\.data'
Set-Location '<repo>'
.\.venv\Scripts\python.exe -m uvicorn litbench.main:app --host 127.0.0.1 --port 8000

# 3) 上传 5 本（sha256 去重，重复上传不会重解析）
Get-ChildItem '<corpus-dir>\*.pdf' | ForEach-Object {
  curl.exe -s -X POST 'http://127.0.0.1:8000/api/papers' -F "file=@$($_.FullName);type=application/pdf"
}

# 4) 按图号检索
curl.exe "http://127.0.0.1:8000/api/figures?q=%E5%9B%BE%204.2.1"
```

证据图（本机、不入库）：`.data/tmp/accept/` 下的 `sheet-*.png`、`overlay-*.png`。
