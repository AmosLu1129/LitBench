# ADR-0001 形态、许可证与复用策略

- 状态：已采纳
- 日期：2026-11-11
- 决策人：项目负责人

## 背景约束

1. 只做 Web 版。
2. 开源，希望被广泛采用。
3. 面向各领域科学研究，按图表占比最高准备。
4. 优先复用成熟开源组件，不重复造轮子。

## 决定

### D1 形态：自部署 Web 应用

否掉桌面（Tauri）方案。
验收标准：一台干净机器 10 分钟内 `docker compose up` 跑起来并解析完一篇。

### D2 许可证：混合

- 仓库根（`server/` `web/` `adapters/`）：**AGPL-3.0-or-later**
- `schemas/` 与 `mcp/`：**MIT**

理由：服务端 copyleft 挡住「拿去做闭源 SaaS」；领域卡片与 MCP 客户端最需要社区贡献，必须宽松。

代价：两套许可证要管；部分高校 IT 与企业合规部门会因 AGPL 拒绝采用。

### D3 复用：依赖 / 隔离 / 不抄

- MIT、Apache-2.0、BSD：直接依赖。
- AGPL、GPL：只在 `adapters/` 下以独立容器或子进程接入。
- 任何 copyleft 代码都不进主镜像，由 `scripts/check_licenses.py` 在 CI 卡住。

关键取舍：把 PyMuPDF 换成 `pypdfium2` + `pypdf`，让 AGPL 暴露面只剩 MinerU 一个容器——而它本来就要单独跑 GPU 镜像。

### D4 图表检索：三路，不是一个列表

- 出处检索（标题 / 作者+年份 / DOI / citekey / 「Fig. 3」）：确定性查找。
- 语义发现（自然语言）：排序查找。
- 主题浏览（不输入）：分面浏览。

搜索框做 intent routing。图挂在 `(paper_version, label)` 上而不是 `paper` 上——版本变了编号会变。

## 后果

**正面**

- 解析、渲染、引用渲染、LaTeX 生成约占 40% 代码量可以直接复用。
- 许可证边界清晰且可自动守。

**负面**

- 归一化层（Docling / MinerU / 自有 schema 三套对齐）预计 2–3 周，必须配 golden test。
- 两套许可证增加贡献者理解成本。

## 复核条件

出现以下任一情况重新评估 D2：

- 连续 6 个月无外部贡献 → 考虑统一为单许可证。
- 主要采用方是高校 IT 且明确禁止 AGPL → 退到 MIT + 隔离。
