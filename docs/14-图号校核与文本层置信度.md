# 图号校核与文本层置信度（阶段化改造）

> 日期：2026-11-11 23:10
> 起因：界面上「无编号」的图其实都有编号——大多数是一个系列图的子图，少数是 OCR 对图注编号识别
> 错误/乱码。用户要求：①规则层 ②双 OCR 交叉校核 ③人工/agent 校核入口 都有必要；
> 并且**文本层质量过低/困惑度过高时降低对现有文字层的置信度，宁可相信两套 OCR 的交叉结果**。

## 0. 改造前盘点（2026-11-11，5 本真实课本 / 352 张图；修订后 348 张见 §8.3）

| 类别 | 数量 | 性质 |
| --- | ---: | --- |
| 已正确带编号 | 181 | — |
| 同页有其他有编号图（系列子图） | 110 | **没做子图归并**，不是 OCR 错 |
| 同页无任何编号（caption 空 / 只有 (a)(b) / 图注乱码） | 59 | OCR 图注提取不全或图注不在图块内 |
| caption 里有图号但没提成 label | 2 | 提取逻辑漏了，可直接修 |

另外确认的编号错误：书 01 的 `图 162 / 图 10凸7 / 图 10/0`（**出版社文字层本身乱码**，不是我们的
OCR）；书 02 的 `图 7 - 25`（空格导致退化成 `fig:7`）；书 03 的 `图 4.e.1`（PP-OCRv6 把数字识别成 e）。

当前能力边界：
- OCR 只跑一遍（MinerU 4.2 flash：PP-DocLayoutV2 + PP-OCRv6_tiny_det + PP-OCRv6_small_rec），
  **没有模型级交叉校核**；OCR 结果也不会再触发 Docling 升级（`_maybe_escalate` 对 `payload.ocr` 直接跳过）。
- 图号只有规则归一化（`LABEL_RE`），没有置信度、没有来源、没有回填、没有子图组概念。
- 有 review 纠错通道，但那是「人发现问题后修」，不是自动校核。

## 1. 目标与原则

1. **每张图都要能回答三件事**：编号从哪来（来源）、有多可信（置信度）、属于哪一组（子图组）。
2. **规则先行**：能用几何 + 编号序列推断的，不花算力；推断结果带低置信标记，进 review 队列。
3. **文字层不是真值**：质量评分低于阈值时，降级为「参考」，以两套 OCR 的共识为准。
4. **误报可接受但必须可纠正**：所有自动推断都可被 review 推翻，且 golden set 回放能量出收益。
5. 不引入 VLM 自动写标签（只允许作为候选字段，人工确认）。

## 2. 三阶段（每阶段独立验收）

### 阶段 1 · 规则层 + 来源/置信度/子图组（先行）

数据模型（迁移 0003）：

- `figure.label_source`：`text_layer | ocr | rule_inherit | rule_repair | rule_infer | review | legacy`
- `figure.label_confidence`：0–1
- `figure.group_key`：同一系列子图的组 key（同书内稳定，`<parent_cite_key>-g`）
- `figure.sublabel`：复用，存子图字母 a/b/c（组内按 bbox 顺序编号）
- `paper_version.text_quality`（0–1）、`paper_version.text_quality_flags`（JSON）

规则（新模块 `litbench/labeling.py`，纯函数）：

1. `canonicalize_label(raw, context)`：容忍空格/全角/OCR 常见替换
   （`e→5`、`O→0`、`l→1`、`S→5`、`B→8`、`凸/^//→-`、全角数字），并用**同书图号序列**校验：
   修复后的编号必须落在本章已见编号的合理邻域（同前缀、序号差 ≤ 阈值），否则保留原值并降置信。
2. `group_subfigures(doc)`：同页、caption 相同/几何相邻、垂直间距小的图块归为一组；
   组内按 bbox 顺序标 (a)(b)(c)；子图行继承父图号（`label_source=rule_inherit`，置信 0.75）。
3. `repair_missing_labels(doc)`：
   - caption 里有图号但 label 为空的 → 补上（`rule_repair`，置信 0.9）；
   - 同页有图号、多个无号图块 → 按阅读顺序继承（`rule_inherit`，置信 0.6）；
   - 章内编号序列恰好缺一个且该页恰好一个无号图块 → 低置信回填（`rule_infer`，置信 0.35），
     只作候选、不自动写引用。
4. `assess_text_layer(doc)`：乱码率、控制字符、重复字符、CJK 比例、文本密度异常 → `score + flags`。
   阶段 1 只**记录**质量分与 flags，不改变流水线；阶段 2 用它触发双 OCR。

验收（阶段 1）：
- 5 本重跑后：无编号 171 → 目标 < 40（其余是低置信候选，可从 API 看到）；
- 110 张系列子图全部有 `group_key` 且继承父图号；
- 书 02 `图 7 - 25`、书 01 可自愈的乱码编号被修（或标低置信）；
- 现有 99 个测试 + 新增用例全绿；figure 接口返回新字段。

### 阶段 2 · 文本层质量门限 + 双 OCR 交叉校核

- worker 决策链改成：
  ```
  pdfium → assess_text_layer
      text_layer=False            → OCR（现有）
      score < TEXT_QUALITY_MIN    → 标记 low_quality_text_layer，强制 OCR + 双通道
      score 正常                  → 现有升级逻辑
  ```
- 双通道 OCR：`OCR_CROSS_BACKENDS=mineru,rapidocr`（skill 允许时可选 docling）。
  第二套用 **RapidOCR（Apache-2.0，独立于 MinerU 的 PP-OCRv6 权重）只识别图注区域的小图**，
  成本是几十毫秒/块，避免整页 Docling OCR 的病态慢。
- 交叉规则：两套对同一图注的图号/文本一致 → 采信共识（`label_source=ocr_consensus`，置信 0.95）；
  不一致 → 保留候选、`label_source=ocr_cross_conflict`，进 review 队列；
  文字层与 OCR 冲突且文字层质量低 → **弃用文字层**（这正是用户要的「宁可相信 OCR」）。
- 验收：书 01/02 的 `图 162 / 图 10凸7 / 图 4.e.x` 被 OCR 共识替换或明确标冲突；
  双通道增量耗时 ≤ 2× 单 MinerU；解析结果可回放。

### 阶段 3 · 校核入口（人工/agent 共用）

- API：`GET /api/figures?label_state=unlabeled|low_confidence` 过滤；
  `POST /api/figures/{id}/label` 改编号（写 `label_source=review`，清低置信）；
  `POST /api/papers/{id}/figures/merge` 批量归并子图组。
- 界面：卡片角标（低置信/继承/冲突）、详情面板显示来源与置信度、候选编号一键确认、
  组内折叠（一个系列图卡片 + 展开子图）、「低置信队列」视图。
- 验收：界面 5 本走查 + 截图；review 后 golden set 回放 recall 不下降。

## 3. 指标（每阶段报告都带）

- `无编号率 = 无 label 的 figure / figure 总数`
- `低置信率 = confidence < 0.6 的 figure / figure 总数`
- `子图归并率 = 有 group_key 的子图 / 同页多图块总数`
- `编号修复数 / 回填数`（按 source 统计）
- `交叉一致率 = 两套 OCR 一致条数 / 双通道总条数`（阶段 2）
- `review 收益 = golden 回放 recall 变化`（阶段 3）

## 4. 风险与取舍

- 子图归并是启发式：允许误报，但必须保留原始子图 bbox/缩略图，review 可拆回。
- 编号序列回填可能给出「看起来合理但错」的号：所以低置信 + 只作候选，不自动用于引用。
- 双 OCR 成本：只对低质量文字层/图注区域，不做全页二次 OCR。
- 文字层质量分是启发式，不是绝对真值；阈值可配置（`TEXT_QUALITY_MIN`），并在基线报告里记录。

## 6. 阶段 2 实施记录（2026-11-12 00:25，已提交）

### 6.1 落地内容

- **第二套 OCR：RapidOCR 3.10（Apache-2.0）+ PP-OCRv4 mobile**（onnxruntime，主进程可用，
  与 AGPL 的 MinerU 无关；MinerU 仍然只走子进程）。只裁**图注区域小图**识别，不整页重跑。
- `ParsedFigure.caption_bbox`：MinerU 的图注子块 bbox 并集（pt），供第二套 OCR 精准裁图。
- 新模块 `server/litbench/ocr_cross.py`：
  - `cross_check_figures`：只校核「值得校核」的图（无编号 / 编号带字母段 / 低置信），
    比对两套 OCR 读到的**原始编号字面量**：
    * 一致且可归一 → `ocr_consensus`（0.95）；
    * 主 OCR 没读到、第二套读到 → `ocr`（0.8）；
    * 字面量不同 → `ocr_cross_conflict`（0.35，进 review）；
    * 两套都读成「图 4.e.1」这类字母段编号 → `ocr_cross_unresolved`（0.35，不硬改成 4.5.1，
      避免把习题图编号猜错）；
    * 高置信、正常数字编号的图直接跳过，不重复烧 OCR（书 03 104 张图只校核 39 张，20s）。
  - `merge_text_layer`：文字层书（书 01/02）跑一套 MinerU OCR，按页/bbox 匹配后，
    **文字层错号/无号以 OCR 为准**（用户要求的方向），一致则升 `ocr_consensus`，
    冲突/无匹配保留原值；不匹配的（同页距离 >120pt）不动。
- worker 接入：主解析是 OCR → 直接局部校核；文字层书质量低/图注有噪声且不会被 Docling
  升级 → 跑 MinerU OCR + 融合。失败只记 warning，不影响整篇解析。
- 迁移 0003 已包含新来源；`persist` 对 `ocr_cross_unresolved` **不写 label_norm**
  （否则 normalize 会退化成 fig:4，污染检索），只留 label_raw 给 review。

## 7. 阶段 3 实施记录（2026-11-12 00:55，已提交）

### 7.1 落地内容

**后端（3 个新接口）**

- `GET /api/figures/label-stats`：待确认计数（unlabeled / low_confidence / conflict /
  unresolved / review_total），给顶栏徽标用。
- `GET /api/figures?label_state=review|unlabeled|low_confidence|conflict|unresolved`：
  按图号校核状态筛选（`review` = 所有需要看一眼的：无号 / 低置信 / 两套 OCR 冲突）。

  置信 1.0；`label=""` 表示「确认这张图没有编号」；「图 4.E.1」这类不可归一的原文允许保存
  （label_norm 置空，避免退化成 fig:4）。
- `POST /api/figures/{id}/group {action: split|merge, member_ids}`：系列子图手工拆开 / 归并
  （拆开用于纠正几何启发式的误归组；归并按阅读顺序标 a/b/c）。

## 8. 阶段 3 补丁：子图字母按阅读顺序 + 二维码过滤（2026-11-12 13:00）

> 触发：用户在界面上人工检验图号标注时发现两个问题——**小的子图 abcd 标反/标错**，
> 以及教材版面里混进了**二维码**（扫码看课件那种，不是文献内容）。大图号已经能识别对，
> 所以这一轮只动这两处，不碰 OCR 选型与检索。

### 8.1 子图字母为什么标反

两个独立 bug 叠在一起：

1. `group_subfigures` 用 `members.sort(key=(bbox.top, bbox.left))` 分配 a/b/c。
   并排子图的上边缘常差 1–9pt（一个高一点），右边那张会排到左边：
   书 05 p2「(a) 等效结构 / (b) 等效电路」被标成 b/a；书 03 p15、书 04 p1 的整行/整 2×2
   同样反过来。
2. `sublabel` 里混进了两种非子图字母：
   - `persist` 写 `fig.sublabel or split_label(norm)[1]`，而 `split_label("fig:4-2-1")`
     返回的尾段是 `2-1` —— 于是「图 4.2.1」在界面上显示成「(2-1)」；
   - 旧 `_sub_letter` 从 `label_raw` 末尾猜字母，OCR 把「图 4.3.2」读成「图 4.3.2J」时
     就把 J 当成子图 j。

修复（`labeling.py` / `workers/run.py` / `routers/figures.py`）：

- 新增 `_spatial_order`：按垂直中心分行（容差 = 中位高度 35%，最小 8pt），行内从左到右。
  这就是「阅读顺序」——2×2 是 a 上左、b 上右、c 下左、d 下右；单列从上到下。
- 每次 `group_subfigures` 先把所有 `group_key/sublabel` 清空再重算：阶段 2 的 OCR 融合
  会改标签，不清会留下上一轮的僵尸组（书 01 之前有 3 个错组就是这么来的）。
- 字母只按阅读顺序分配，不再从 `label_raw` / 图注字母猜——图注里的 (a)/(b) 会被版面
  模型错配到相邻块（书 04 p1 的「(b)」就挂在 d 块上）。
- `persist` 只写 `fig.sublabel`；人工改图号接口用 `label_norm` 末尾单个 a–z 作为字母，
  「图 4.2.1」的 `2-1` 不再进 `sublabel`。

### 8.2 二维码过滤

- 新模块 `server/litbench/figure_filter.py`：`cv2.QRCodeDetector.detect` 到二维码四边形，
  要求 **coverage ≥ 0.42**、**图块最长边 ≤ 120pt**、长宽比 0.35–1.8，三条同时满足才删。
- 为什么不靠解码：课本二维码缩略图只有 62×62，实测 4 张全部 `detectAndDecode` 失败；
  靠几何覆盖率更稳。
- 为什么不误杀「大图里含一个小二维码」：arXiv 图实测 coverage 0.01–0.21、尺寸 ≥170pt，
  两条阈值都拦住了；散点图/频谱图的误检 coverage ≤0.40。
- worker 在 `parser.parse()` 之后、规则层之前调用 `drop_qr_figures`；被删的图不进库、
  不参与归组。开关 `FILTER_QR_FIGURES=true`（默认开）。
- 依赖 `opencv-python-headless`（Apache-2.0；缺 cv2 时静默跳过过滤，不影响解析）。

## 9. 界面增强：系列浮层 + 用户增删图（2026-11-12 13:50）

### 9.1 图 4-50 的识别修复

- **现象**：书 04 p1 图 4-50 是 5 个子图（a)–(e)），但库里只认出 4 块，字母整体错位。
- **根因**：OCR 把「图 4-50a」读成「图 4-500」，`label_norm=fig:4-500` 与父号
  `fig:4-50` 不是同一个 norm，于是它被当成独立图，没能进入系列组。
- **修复**（`labeling.py::group_subfigures`）：新增「读坏的子图号」重归组判据——
  图注以 `(a)`/`a)` 开头 + 候选号尾段是某个父号尾段的前缀扩展（只多 1–2 个字符）
  → 并回几何最近的父号，并**强制继承父号**（即使这张图来源是 OCR，也覆盖）；
  统计里新增 `reassigned`。
- **数据**：重跑迁移后书 04 p1 图 4-50 = 5 块，字母 a–e 与书上 (a)–(e) 一一对应。
  用户此前在界面把「图 4-500」手动改成「图 4-50」（`label_source=review`），
  归组按最终标签生效；这条人工改号现在也会在重解析时按 page+bbox IoU 回填。
- **测试**：`test_misread_subfigure_number_rejoins_group`。

### 9.2 系列图集交互（背景虚化浮层）

- **图标区分**：图集卡片左上角是「重叠双框」靛蓝胶囊（图集 · N）；单图是「单框」
  深灰胶囊（单图）；手动添加的图右上角多一个绿色「手动添加」。
- **点开 = 浮层**：点图集卡片打开系列浮层（`role=dialog`），`backdrop-filter: blur(7px)
  saturate(.9)` 让背景虚化；浮层内只有子图卡片可交互，其余页面元素点在背景上即收起。
- **收起**：`Esc`、右上角 ✕、点背景三种方式；收起后背景恢复可交互、页面滚动解锁
  （`body.overlay-open`）。
- **选图**：浮层里每张子图显示图号+字母、缩略图、图注、页码（含「子图/手动」标记）；
  点任一张 → 收起浮层并打开该图详情。原来的「原地展开」已移除，列表里一组只出现一张卡。
- **卡片信息行瘦身（2026-11-12 14:00）**：图号后面不再重复「图集」/「点击展开」；
  「已确认」（绿）、「已判错」（红）、「OCR 一致」（蓝）、「修复」（紫）压成 9px 彩色圆点，
  文字只进 `title` tooltip；页码从图号行移到缩略图右下角的深色小胶囊；
  图号行只剩「图号 + 低置信才出现的『待确认』文字 + 状态圆点」。
