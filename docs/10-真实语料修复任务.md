**5 份 5 中 0。** 分两类故障，性质完全不同：

### 故障 A：整页图被当底纹丢掉（有文字层那 2 本）

`server/litbench/adapters/pdfium_parser.py` 的 `_drawing_primitives()`：

```python
if w * h > page_area * 0.9:
    continue      # 几乎整页 → 版面底纹，不是图
```

这条规则对 arXiv 论文是对的（整页是矢量正文，插图是小 image 对象）。但**扫描版课本每页就是一整张图**，面积 ~100%，被这条规则全部丢弃 → `figures=0`。

后果比"质量差"严重：状态是 `parsed`，caption 认出来了（35/31 个），库里能搜到"图 10-1"，点进去**没有图**。而且 review 通道也修不了——没有 figure 记录可复核。

### 故障 B：无文字层直接空转（另外 3 本）

`server/litbench/workers/run.py:192`：

```python
paper.status = "parsed" if doc.text_layer else "needs_ocr"
```

只是**打个标记**。往下游 `_maybe_escalate()` 只按「caption 缺失 / caption 过短」判弱，无文字层的文档连 caption 都没有，走不到升级分支，也没有 OCR 路径 —— 文档停在 `needs_ocr` 上再无下文。

`docs/09` §12 里「扫描件 OCR / MinerU」本来就是 ⬜ 未做；Docling 的 OCR 只活在一句注释里（要 `docker compose --profile ocr up`），而 §13-4 写着 Docker 从没真正启动过。

## 三、分四步做，一步一交

### 第 1 步 · 扫描页不再当底纹（先修故障 A，不依赖任何新依赖）

- 在 `_drawing_primitives()` 里区分**两种"整页"**：
  - 页面是矢量正文 → 维持原样（大对象仍当底纹丢弃）；
  - 页面**只有一张覆盖 ≥90% 的位图、且几乎没有 text block** → 这是扫描页，标记 `scanned_page`，**保留**它作为候选绘图基元。
- 图框改成 **caption 锚点驱动**：已知 caption 的 bbox，在它上方（或下方，按 layout）找最近的空白带，
  在整页渲染图上切出 figure。允许误报——`docs/09` 的原则是「误报可接受，但必须有纠错通道」。
- 现在这两本的 caption 已经能认出 35 / 31 个，位置信息是有的，等于锚点白送。
- **验收**：2 份有文字层的切片 `figures > 0`；随机抽 10 张 figue，缩略图里不是正文。

### 第 2 步 · 无文字层接 OCR（用户明确要的：配置 OCR 模型，MinerU 之类）

- 目标后端：**MinerU**（`__init__.py` 里已留 `MineruParser` 桩）。也可先上 Docling 的 OCR 作为过渡档。
- **许可证纪律必须守**：AGPL 组件不能进主进程 import，只能走**独立容器或独立子进程**（这是 `adapters/__init__.py` 自己写的规矩）。
  本机没装 Docker，所以优先方案是**独立子进程**（`subprocess` 起 MinerU 的 CLI/服务），这符合你们自己的纪律。
- 实际要做的事：
  1. 装 MinerU（CPU 模式即可，先用小模型；注意它有几百 MB 权重，装完记进 `docs/04` 依赖清单）；
  2. 新增 `MineruParser` 的真实实现（现在是 `# pragma: no cover` 的桩）；
  3. **页级触发**：`text_layer=False` 时自动排一个 `backend=mineru` 的 parse job，而不是停在 `needs_ocr`；
  4. 失败要能降级：OCR 挂了 → 文档标 `needs_ocr` 且**带失败原因**，不能静默。
- **验收**：3 份无文字层切片 `blocks > 100`、`figures > 0`。

### 第 3 步 · 让扫描件在界面上真的能用

- 原文查看器（`web/src/PdfViewer.tsx`）对扫描页也要能出红框、能拖框修正（第 1 步已经做出框了）。
- 缩略图重裁（上一轮刚做的 `POST /review` 带 bbox 重裁）在扫描页上要能工作。
- **验收**：手工在界面上把 5 份都走一遍，截图存 `docs/`。

### 第 4 步 · 补一条"真实语料"回归，替代拍脑袋的度量

- 新增 `scripts/eval_real_corpus.py`：对 `<corpus-dir>\` 跑一遍，输出
  「每份的 blocks / figures / 图注-图配对成功率 / 耗时」到 **`docs/13-真实语料基线.md`**
  （原定 `docs/11-真实语料基线.md`，但 `docs/11` 已被 OCR 双路径对比占用）。
- 这个脚本以后每次改解析器都跑，作为**真实场景的可信指标**（arXiv 那 10 篇继续留作"最规范版面"的对照）。
- **验收**：脚本能跑，基线数字写进文档。

## 四、红线（别踩）

- **不许为了过验收把阈值调松充数**。`figures > 0` 必须是"真的框住了图"，不是把整页当一张图凑数。
  如果只能做到"整页一张图"，那要明确标注为 `figure_level=page`，并在文档里写清这和"框到具体图"的区别。
- **不许动 arXiv 那 10 篇的行为**。改完跑一遍 `scripts/p0_report.py`，与 `docs/05` 的基线对比，写差异。
- **不许截教材原图冒充解析结果**；验收截图要能看出是从 PDF 里框出来的。
- 语料在 `<corpus-dir>\`，**只读**，不要往里面写解析产物。
- 上游课本原件在 `<local-textbooks-dir>\`，**绝对不要动**（用户还在用它们写作业）。
